# 学的是史 — Web 站点长期发展路线设计

## 概述

本文档为《学的是史》Web 站点（`http://118.178.140.171:9090`）制定长期发展方向。核心目标：**正确实现基本功能 + 可持久化更新**。

与微信小程序（TASKS 目录下任务树）为两条独立产品线，数据模型保持一致，内容可共享，但各自迭代、互不阻塞。

---

## 1. 当前状态

项目已完成第二阶段重构：将单文件 `index.html` 拆分为 HTML/CSS/JS/JSON 模块结构。当前技术栈：

- 原生 HTML / CSS / JavaScript
- JSON 静态数据（通过 `fetch` 加载）
- LocalStorage 本地持久化
- 无框架、无构建工具、无后端

**现存问题：**
- 大量功能为 stub/mock 占位（如讨论区帖子发布仅 toast、AI 助手为模拟回复、播客无真实音频）
- 部分内联脚本仍未迁移到 JS 模块
- JSON 数据不完整，部分内容仍硬编码在 HTML 中
- 内容更新需手动编辑 JSON 文件 + git commit + 部署脚本

---

## 2. 三阶段路线图

### Phase 1：功能补完（当前 → 约 4-6 周）

**目标：** 所有 stub/mock 清理完毕，每个功能做到"数据真实、交互可用、流程闭环"。

按优先级 A→I 依次推进：

| 优先级 | 模块 | 当前状态 | 目标 |
|--------|------|----------|------|
| **A** | 名词解释 | 基本可用，JSON+搜索+详情+收藏 | 扩充名词库（≥50条），补全详情（地图、相关名词），搜索边界处理 |
| **B** | 时间轴 | 基本可用，朝代切换+缩放+事件详情 | 补全各朝代事件数据，修复拖拽/缩放边界 bug，时代特征数据迁移到 JSON |
| **C** | 人物专题 | 内联硬编码 6 人，SVG 关系图 | 迁移到 people.json，扩充至≥30 人，关系网支持点击导航 |
| **D** | 影视书目 | film.js 已完成，待看栏 LocalStorage | 充实影片/书目数据，榜单逻辑完善 |
| **E** | AI 播客 | 模拟播放器 | 接入真实音频文件（服务器托管），播放器完整可用 |
| **F** | 讨论区 | 模拟帖子+评论 | 帖子发布即时更新（P1 先用 LocalStorage），评论展开/回复可用 |
| **G** | 打卡签到 | 基本可用 | 统计数据联动，连续打卡提示 |
| **H** | 科学备考 | 思维导图基础可用，无刷题 | 思维导图笔记完善，补充基础选择题/测验（前端实现） |
| **I** | 首页热点 | 硬编码外链 | 从 hot-articles.json 渲染，支持朝代筛选，数据可维护 |

**并行清理：**
- 将 `index.html` 剩余内联脚本迁移到对应 JS 模块
- 统一 toast 文案（去掉所有"功能开发中"）
- 补齐单元测试覆盖

**验收标准：** 全站无"开发中"占位提示；每个页面功能闭环可用；控制台无阻断性错误。

### Phase 2：内容管线（约 4-8 周）

**目标：** 非技术人员可通过 Web 界面编辑内容，内容更新流程规范化，支持从第三方平台精选内容。

#### 2.1 编辑型内容 — Decap CMS

```
内容编辑者 → 登录 /admin → 编辑 → 保存
  → GitHub commit → Webhook → 服务器 deploy.sh → 线上更新
```

每种 JSON 数据类型对应一个 Decap Collection：

- `nouns` — 名词（标题、分类、朝代、正文、相关名词、地图引用）
- `timeline-events` — 时间轴事件（年份、朝代、标题、描述、关联连线）
- `people` — 人物（姓名、别名、朝代、身份、事迹、关系、年表、评价）
- `films` — 影视书目（标题、类型、封面、简介、评分、朝代关联）
- `podcasts` — 播客（标题、分类、时长、音频文件引用、简介）
- `hot-articles` — 热点文章（标题、摘要、来源、朝代标签、链接）

#### 2.2 策展型内容 — 内容聚合

热点文章模块可持续发展：

| 来源 | 方式 | 优先级 |
|------|------|--------|
| 人工精选 | 通过 CMS 维护推荐文章列表 | P2 立即 |
| RSS/Atom 订阅 | 服务器定时脚本抓取 | P2 后期 |
| 微信公众号 | 手动精选填入 CMS | P2 立即 |

#### 2.3 部署联动

```
GitHub push → Webhook (或轮询) → 服务器 pull → ./scripts/deploy.sh
```

JSON 内容变化时触发自动部署，无需人工登录服务器。

**验收标准：** 可通过 `/admin` 路径编辑任意内容类型并发布；内容变更自动部署到服务器。

### Phase 3：轻量后端（约 4-6 周）

**目标：** 用户交互数据（讨论区、打卡、收藏、待看栏）实现服务端持久化，支持跨设备同步。

#### 3.1 技术选型

- **运行时：** Node.js + Express
- **数据库：** SQLite（单文件，零配置，够用）
- **用户标识：** 前端生成设备 UUID，无需注册登录
- **部署位置：** 现有服务器 `118.178.140.171`

#### 3.2 API 设计

```
POST   /api/posts                创建帖子
GET    /api/posts?cat=&page=      获取帖子列表
POST   /api/posts/:id/comments    发表评论

POST   /api/checkin               今日打卡
GET    /api/checkin?month=        查询打卡记录

GET    /api/favorites?type=       获取收藏
POST   /api/favorites             添加收藏
DELETE /api/favorites/:id         取消收藏

POST   /api/watchlist             更新待看状态
GET    /api/watchlist             获取待看列表
```

#### 3.3 目录结构

```
server/
├── server.js          # Express 入口
├── db/
│   └── history.db     # SQLite 单文件
├── middleware/
│   └── device-id.js   # 设备标识中间件
└── package.json
```

#### 3.4 前端适配

- 封装 `src/js/api.js` 统管 API 调用
- 各业务模块优先读 API，失败时回退 LocalStorage
- 设备 ID 首次访问时生成并存储

#### 3.5 分步上线

```
P3a: 讨论区后端 → P3b: 打卡同步 → P3c: 收藏/待看同步
```

**验收标准：** 清除 LocalStorage 后讨论区帖子仍存在；不同设备看到相同的打卡/收藏数据。

## 3. 与微信小程序的关系

```
                    《学的是史》产品矩阵
                          │
    ┌─────────────────────┼─────────────────────┐
    ▼                     ▼                     ▼
Web 站点              微信小程序             未来可能
(本项目)              (TASKS/v2)             (PWA/App)
    │                     │
    │  Phase 1-3          │  M0→M6
    │                     │
    └─────────┬───────────┘
              │
    共享资产：JSON 数据模型 / 内容规范 / 品牌视觉
```

- 两端独立迭代，不互相阻塞
- JSON 数据 schema 保持一致，Decap CMS 内容可复用到小程序 Mock 数据
- 但不强制两端功能同步——Web 站定位轻量内容站，小程序定位重交互学习工具

---

## 4. 设计原则

1. **兼容优先：** 每次改动后站点仍可通过 `python -m http.server` 静态运行（P3 之前）
2. **渐进增强：** 后端可选项（P3）不影响前端独立使用
3. **YAGNI：** 不做框架迁移、不做技术栈升级、不超前设计
4. **内容先行：** 内容质量优先于炫酷交互
5. **可回退：** 每步改动可独立回滚

---

## 5. 不纳入范围

以下明确不在本路线图内：

- Vue / React / Svelte 等前端框架迁移
- Vite / Webpack 等构建工具引入
- TypeScript 全面迁移
- 微信小程序开发（已有独立 TASKS 规划）
- 真实微信 OAuth 登录
- AI API 真实接入（保留模拟，待小程序端验证后再决定）
- 大规模 UI 改版
- PWA / Service Worker
